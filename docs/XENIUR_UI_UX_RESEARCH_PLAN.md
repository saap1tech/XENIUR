# XENIUR — product, UI/UX and first-run plan

Research and repository review: 25 September 2026. This is a design and implementation plan, not a claim that proposed features already work. No API keys were entered and no paid API calls were made.

## 1. Product thesis

**XENIUR is a home for purposeful projects on a PC.** A person brings a question, file, page, sketch, or idea; XENIUR helps them turn it into a visible path from sources to decisions to work to a result. AI is a capable tool inside that path. The person owns the goal, evidence, tradeoffs, edits, and final choice.

The universal job is not “generate content.” It is **keep a meaningful project moving without losing judgment or context**. That applies to a trip, small business, 3D object, lesson, job search, home improvement, software project, or creative work. Start with three demonstrable journeys: plan a trip, make a physical/digital thing, and investigate a purchase or claim. These exercise the same core primitives without promising every domain on day one.

The main loop is **Bring in → See → Choose → Make → Check → Share/finish → Resume**. Every screen should show the current project, the current object, the next meaningful move, and what changed. If a feature cannot fit into that loop, keep it in a contextual detail view.

## 3. Current UX diagnosis

1. **Too many simultaneous explanations.** World can show a goal bar, progress sentence, focus label, density selector, plan/material switch, zone counts and states, stage reason, scene, proposal tray, next step, next action, prompt dock, and inspector. The same “what next?” question appears in several places. The Home screen has project cards, Today rows, creation cards, trust counts, economy, and editorial/footer copy. This raises scanning cost even though much of the content is useful.
2. **Abstract visuals often encode the system instead of the user's thing.** The orbit, generic glyphs, support counters, and folder cover art communicate XENIUR's internal model. A trip should show a map/route and decisions; a 3D project should show its model and transformation stages; an investigation should show claims linked to their sources. The actual artifact should dominate the stage.
3. **Labels and metaphors drift.** “World”, “Object”, “Material”, “Today”, “Where I stand”, “Ask”, “Focus”, “Arena”, and “Your models” belong to different vocabularies. Prefer the person's words: Projects, Sources, Choices, Work, Results. Use system vocabulary in details and documentation.
4. **Visual density is adjustable, but information priority is not yet decisive.** Compact/comfortable/detailed modes change disclosure, yet the shell still places numerous independent regions on screen. One clear focal object and one next move would create a stronger first glance.
5. **Model setup is truthful but fragmented.** Keys, price verification, model availability, actual transport, and tool capability are separate concepts. The current provider list can verify a key but cannot fully configure the requested set of services from the UI.
6. **Community and rewards are more prominent as concepts than daily utility.** The user needs a useful project connection before they need scores, a feed, or a badge. Current local Rhythm already makes the right distinction: predictable cadence, relevant content, opt-in modes, and a meaningful action streak. It is disabled and has no discovery service.
7. **Cross-platform polish needs a specific audit.** The desktop shell has macOS-oriented fonts, shortcuts, and paths; the product aim is broader PC use. Test Windows/Linux file paths, keyboard conventions, screen scaling, mouse-only operation, assistive technology, and offline behavior.

The interactive app was not visually captured in this review. Node 22 was selected, but the dev server could not bind its local port in this environment (`EPERM`); the in-app browser also blocked the local preview file by URL policy. The diagnosis above is based on current components, styles, preview markup, and successful TypeScript checking. A visual QA pass on the running desktop app is an explicit first implementation gate.

## 4. Research translated into design rules

- **Use images and spatial structure to explain the work, short labels to explain actions.** Novel icons alone are hard to understand. Pair a distinct symbol with a one-to-three-word label in navigation and consequential actions; test comprehension before hiding any label. [Nielsen Norman Group, icon usability](https://www.nngroup.com/articles/bad-icons/), [application design mistakes](https://www.nngroup.com/articles/top-10-application-design-mistakes/).
- **Reveal detail at the moment of need.** Show one primary action, a small number of related alternatives, and a clear path to full detail. This is a better response to choice overload than simply removing capability. [Nielsen Norman Group, progressive disclosure](https://www.nngroup.com/articles/progressive-disclosure/).
- **Make AI increase scrutiny.** A 2025 survey of knowledge workers associated higher confidence in generative AI with less reported critical thinking; the authors observed a shift toward verification, integration, and oversight. Design evidence inspection, alternative generation, and personal rationale into decisions. This is an association from self-reports, not proof that any specific UI raises critical thinking. [Microsoft Research, CHI 2025](https://www.microsoft.com/en-us/research/publication/the-impact-of-generative-ai-on-critical-thinking-self-reported-reductions-in-cognitive-effort-and-confidence-effects-from-a-survey-of-knowledge-workers/).
- **Reward useful progress, not app time.** Reviews find that gamification can improve engagement, but effects can fade and extrinsic rewards can displace intrinsic motivation. Reward a verified claim, resolved blocker, revision, human feedback, or delivery; do not reward opening the app or scrolling. [Gamification review](https://pubmed.ncbi.nlm.nih.gov/37636393/), [extrinsic reward meta-analysis](https://pubmed.ncbi.nlm.nih.gov/10589297/).
- **Offer surprises at task boundaries and preserve choice.** Defer a discovery card until a saved step, completed action, or chosen pause. Show why it is relevant and let the person open, save, dismiss, or defer it. A forced, unskippable video would undermine control, interrupt work, and cannot reliably suppress YouTube's related-video paths. [Microsoft Research on interruption breakpoints](https://www.microsoft.com/en-us/research/video/paying-attention-to-interruption-a-human-centered-approach-to-intelligent-interruption-management/), [YouTube player parameters](https://developers.google.com/youtube/player_parameters), [YouTube developer policies](https://developers.google.com/youtube/terms/developer-policies-guide).
- **Use natural cues carefully.** Curved forms and spatial continuity may help the interface feel calm, but aesthetic preference varies by person and context. Apply organic motion to transitions and connections, not to every control. Keep motion optional and task focused. [Curvature review](https://pmc.ncbi.nlm.nih.gov/articles/PMC10091794/), [Apple motion guidance](https://developer.apple.com/design/human-interface-guidelines/motion).
- **Visual does not mean inaccessible.** Every icon needs an accessible name, every state needs a cue beyond color, drag needs a non-drag alternative, and motion needs a reduced-motion mode. [WCAG 2.2](https://www.w3.org/TR/WCAG/).

## 5. Proposed visual language: a living project landscape

The center is a **Project Landscape**, not a blank chat pane or an abstract infinite canvas. A project is a small set of visible objects arranged along a path: **Sources → Choices → Work → Results**. The path is stable across domains, while object previews are domain-specific. Connections show why one item matters to another. A selected object rises forward; unrelated material recedes. People can zoom from overview to one object without losing the path.

### A visual grammar people can learn

| Meaning | Visual form | Interaction |
| --- | --- | --- |
| Source | Square tile with real page/photo/file thumbnail and source badge | Open original, highlight passage, drag or link to a claim |
| Question/uncertainty | Open circle or gap in a connection | Inspect what is missing; attach evidence or mark unknown |
| Choice | Fork with 2–3 option tiles and visible tradeoff markers | Compare, state reason, record what would change the choice |
| Work | Object preview plus short sequence of transformations | Edit directly, run suggested step, review result |
| Result | Finished object with an export/share edge | Check requirements and origin, then deliver |
| Human action | Hand-drawn stroke/initial marker | Inspect person's note or revision |
| AI action | Distinct woven/dotted marker with provider disclosure | Inspect input, model, cost, and output |

Shape, position, icon and brief label must work together; color only reinforces status. Use real project imagery as the visual anchor. Use a restrained palette based on paper, graphite, water/mineral greens and one action accent; offer a light and a dark theme. Give surfaces a tactile but quiet material feel. Motion follows object movement or state change, with short, interruptible transitions. Offer an optional low-volume natural soundscape only in focus sessions, muted by default and never as the sole signal.

### Three screen sketches

**First launch:** a calm setup canvas with five provider tiles grouped by role: Thinking (OpenAI and Gemini), Image (an actually supported image model), 3D (Meshy), Motion (Runway). One tile expands at a time to paste a key, verify access, choose models, and set a spend cap. A persistent “Continue locally” path is available. No false “ready” checkmark for a stored key without a working adapter.

**Home:** one large “Continue [project]” visual with the current object and next move; below it a small gallery of projects; a compact “Needs you” strip for approval, stale decision, or broken input. “New project” starts from **Idea / File / Link / Continue package**. Economy, trust detail, and community live in contextual drawers.

**Project:** the center shows the actual artifact or a meaningful domain view. A thin path rail shows Sources, Choices, Work, Results and current position. A contextual side panel shows at most one next move plus “why” and “other options.” AI controls are verbs tied to objects (summarize source, compare options, sketch variant, make 3D, animate), not a permanent model picker. The person can always open the model and cost decision before execution.

## 6. First-run model setup and settings specification

**Launch rule:** show the model setup as the first screen whenever there is no saved, enabled model that can actually run in this installation. Re-evaluate on every launch and after key removal. If at least one working model remains, go directly to Home. “Continue locally” lets a person use import, research, local tools, and manual planning during this session; setup appears again on the next launch while no model is configured. If the machine is offline or its keychain is unavailable, explain this plainly and keep local work usable.

**Flow:** (1) choose provider, (2) paste key into the OS-protected store, (3) verify with a safe list/access call, (4) discover the models this account can use, (5) select the model(s) for the provider's supported roles, (6) review current price/source date and set per-action and monthly caps, (7) run a bounded, explicitly confirmed test only if a list call cannot establish execution. Display states: absent, key stored, access verified, model selected, adapter ready, price checked, ready; plus invalid key, insufficient permission, quota, unavailable model, offline, and unsupported adapter. A credential is never shown again and can be replaced or removed.

**Settings:** one “AI and tools” view with provider cards, selected model by task role, routing preference (“XENIUR chooses” by default; “Ask every time” optional), private/local-only material setting, spend caps and usage, test connection, replace/remove key, and clear explanation of data leaving the PC. Separate text/reasoning models from image, 3D, and video generators. For each AI action, show the selected tool, why it was chosen, estimated cost, and alternatives only when the user opens details.

**Provider scope:** OpenAI's documented GPT-5.6 Luna/Terra/Sol IDs are `gpt-5.6-luna`, `gpt-5.6-terra`, and `gpt-5.6-sol`; do not infer account entitlement from documentation. Discover the user's accessible IDs through the models endpoint. [Official OpenAI model guidance](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.6), [models API](https://developers.openai.com/api/reference/cli/resources/models). Gemini's model-list endpoint can supply supported actions. [Google models API](https://ai.google.dev/api/models). Meshy image-to-3D and Runway video are asynchronous generation products with their own adapters, job states, prices, and output validation; a text-model registry entry cannot substitute for them. [Meshy API](https://docs.meshy.ai/en/api/image-to-3d), [Runway API](https://docs.dev.runwayml.com/guides/using-the-api/).

**Implementation gate:** replace the marker-file-only first-run decision with a readiness query from main-process services. Extend typed provider capability records and selection persistence. Build real Google/Meshy/Runway transports and current OpenAI model entries before marking them selectable. Preserve encrypted key storage; never expose the key over the renderer bridge after initial submission. Add price provenance and fail-closed spend checks before live metered calls.

## 7. Critical thinking as the product's daily habit

The default decision interaction is a **Choice Fork** with two or three visible options. Each option has a tiny “helps / costs / unknown” panel. To commit, the person marks at least one reason and can optionally state one reason the choice might be wrong. For meaningful decisions, XENIUR asks “What evidence would change your mind?” and stores the trigger. AI may draft options or locate evidence, but labels its suggestions and links back to sources. The person can deliberately accept uncertainty without pretending the choice is settled.

The default research interaction is **Claim ↔ Source**. Capture a passage, turn it into a claim, show support/contradiction edges, and distinguish “source says,” “AI inferred,” and “I observed.” When a source changes, the related decision receives a clear review marker. This makes critical thinking a small action in the path instead of a lecture or a long form.

For generated work, add a compact **Human Pass** before sharing: “What did you change?”, “What do you stand behind?”, “What still needs checking?” The existing process record and proof pages can support this, but do not claim that logs prove originality or quality. Human interaction means asking a peer for a specific critique and showing what changed as a result.

## 8. Motivation, discovery and community

**Predictable core:** completion of a meaningful step produces a visible change in the project landscape, a saved checkpoint, and a clear next move. A daily streak counts an action that advances a project, with a grace day and no shame/penalty screen. The user can turn it off.

**Occasional discovery:** an optional “Found for this project” card appears at a natural pause, capped by the person's settings. Candidate types: a source that challenges a current claim, a tutorial matched to the next blocked step, a related object in another project, an expert/community thread relevant to a question, or a concrete opportunity that the person can inspect. Each card shows **why now, where it came from, and one possible next move**. Relevance should be based on goal, current step, consented sources, freshness, and credibility; never on maximizing screen time. If nothing clears the threshold, show nothing. No autoplay or unskippable media; provide a focused reader/player with a return-to-project control. Any contact suggestion requires verified relevance and explicit user initiation before outreach.

**Community:** begin with project-linked critique circles, not an open infinite feed. A person can share a selected result or question, define what feedback they want, and invite a small circle. Posts are visual project cards with the work, context, specific question, and process disclosure. Replies attach to an object or decision; high-quality critique earns acknowledgment from the author. Challenges have opt-in timeboxes, clear output criteria, accessible untimed alternatives, and a review step that values reasoning and craft. Existing signed packages and publisher trust can seed portability, but server identity, moderation, abuse controls, privacy, and consent are prerequisites for a genuine in-app community. Avoid a public ranking of raw hours, output volume, or streaks.

**Experiments:** compare project progress and comprehension, not only engagement. Measure voluntary return to an unfinished project, time to resume, useful steps completed, decisions with cited evidence, reversal/review quality, discovery-card usefulness, and user-reported fatigue/control. Watch for surprise cards causing interruption, competitive pressure, low-quality submissions, and overreliance on AI.

## 10. Validation with real people

Recruit people with different PC work: an everyday planner, student/researcher, creator/3D maker, small-business operator, and developer; include keyboard and assistive-technology users. Give each an unfamiliar project and ask them to start, find what to do next, compare two options, find the source of a claim, change their mind, and resume after interruption. Record task success, time to first useful action, wrong turns, icon comprehension, density preference, and whether a surprise helped. Test the screen at different scaling, themes, languages, and reduced-motion settings. Iterate until common actions are understood without a tour or a paragraph of explanatory copy.

The design promise is **less reading before action, more evidence before commitment**. Those two requirements belong together.

## 11. Implementation status (2026-09-25)

The first screen now checks for a selected, accessible, priced AI model. If none is ready, it opens the connection canvas; **Continue locally** dismisses it for this run, and it returns on the next launch. Keys remain in Electron safeStorage. Selection and successful model-list verification are stored without credential bytes. OpenAI Luna, Terra, Sol and Gemini 2.5 Pro, Flash, Flash-Lite have current dated text-token prices and callable transports. Ollama can be selected after a local model check. The settings canvas is reachable from Home, the command palette and tasks that need a key; it supports replacing/removing keys and per-request/monthly AI thinking limits. Anthropic, Meshy and Runway can hold keys but clearly remain unavailable for live work until their adapters and prices are finished.

Home is now a visual return path with a project landscape, compact urgent situations, a gallery of projects, and direct access to connections. Gallery cards use the latest image from that project where available, with a drawn fallback. Home, setup, choices, and discoveries now use the same brighter graphite, Avenir, and lime identity, including the original logo. The Project screen has a clickable Sources → Choices → Work → Results path, adopted-step progress, and a direct Choice Fork for recording a decision with a chosen option, reason, counterargument or explicit skip, and an optional review trigger. Existing source, evidence, undo, approval, export, and project position features remain available in their existing views. The Decision Card now displays the options as a visible fork.

The Web screen now shows a three-stage page → source → project route, a shorter capture flow, and a direct route to account browsing. Browser sessions opened from a project carry that project's title and current step in a side panel with a capture-and-return path. Challenge feeds show a visual add → verify → choose route and compact outcomes; detailed failures and technical safeguards remain available on request. The arrival sheet exposes the existing local report function with a reason and optional note, and explicitly says that no moderator receives it. This is a local safety control, not a moderated community.

The process-sharing dialog now asks for a Human Pass: what the creator changed, stands behind, and still needs to check. Those deliberately public answers appear in the generated proof page and are covered by its integrity hash.

Project discoveries use the existing local graph and fixed 90-minute cadence. They are offered only after completed plan steps, next actions, or goals, at most twice a day, with no unrelated fallback. Repeated questions and review prompts are suppressed; a skip lengthens the next interval. Each card names its connection to the current project and can be explored or dismissed. The project screen has an on/off control. No external recommendation feed, autoplay video or contact action was added.

Meshy key access can now be checked without starting a paid job through its documented free balance endpoint. The balance is visible in the connection screen. Runway still has no safe free key check in this build. Both are clearly marked as stored-key connections, not active generators.

**Still to implement:** safe, priced Meshy and Runway generation jobs; an image-generation provider; external research/tutorial relevance and credibility checks; a genuine moderated, consent-based critique circle; reusable thumbnails/previews for every modality; light/dark theme choice; and real-user walkthroughs. Those depend on live account entitlements, provider prices, moderation infrastructure, and visual review on supported machines. The current build makes no claim that a stored Meshy or Runway key can generate content. TypeScript, the desktop bundle, and focused UI tests pass. The full suite passed 66 of 69 files before a one-millisecond ticket-test fixture was corrected; both remaining failing suites require Blender, which exits before returning a result in this sandbox. A screenshot pass was attempted but the local browser process aborted under sandbox restrictions, so visual evaluation on a running desktop installation remains open.

## 12. Continued implementation (2026-09-28)

The new **Work State / Sharpen this** path now assesses observable project conditions and offers four or five grounded thinking moves. Answers create persistent linked notes, explicit checks, review actions, or test steps in the real project. Recall hides the recorded rationale until the person answers or deliberately opens it. Stale evidence invalidates unfinished sessions; keeping a decision cannot clear disagreements. The feature works locally without model keys. See [the implementation report](XENIUR_WORK_STATE.md).

Home, connection setup, browsing, workflow entry points, and the optional work-state overview now use three original XENIUR illustrations. The latest art direction replaces the previous figures with men with completely blank faces and adds a matching research scene. The original mark, Avenir typography, graphite and lime palette remain consistent, with brighter shared surfaces. [Illustration direction and exact generation prompts](../brand/illustrations/README.md).

The earlier browser restriction was resolved for this review. Thirteen screenshots now document the actual renderer at full and compact desktop widths. The browser walkthrough completes all five thinking moves, checks hidden recall, pause/resume, saved comparison, explicit source/test actions, and first-run setup with no page errors. It also identified and fixed a circular process-record refresh in the project screen. The preview uses clearly selected sample data; SQLite persistence is verified independently. The full test run and separate Blender verification pass across all 71 suites; current Work State, Sharpen, style checks, TypeScript, and the desktop bundle also pass.

The live generation adapters, external recommendation services, moderated community, theme switching, and recruited-user research listed above remain unfinished. These implementation results do not establish universal icon comprehension or task success with real users.
