# XENIUR — repository audit and verified baseline

Reviewed **5 September 2026** in `/Users/developer/development/Xeniun`. This is an implementation review supporting the [strategy](/Users/developer/development/Xeniun/docs/XENIUR_STRATEGY.md) and [revised V1 plan](/Users/developer/development/Xeniun/docs/XENIUR_V1_PLAN.md), not a comprehensive penetration test.

**Finding.** XENIUR already has a substantial architectural prototype: ten workspace packages, an Electron/React application, real local providers, a persistent graph/queue, and an offline cross-modality demonstration. The package boundaries are worth preserving. Several advertised guarantees are not yet enforced across the integrated application.

No applicable `AGENTS.md` was found in the inspected project/ancestor paths.

**2. What is already strong**

- The graph stores representation-level action inputs/outputs with roles and a materialized edge index. The demo exercises identity across actual PNG/GLB/STL files.
- Version APIs support branching and nondeleting undo at the repository layer.
- SQLite/WAL and the filesystem blob store keep deployment simple.
- Local sharp/FFmpeg/Blender implementations and visible mock origin provide an offline engineering path.
- The Brain has a schema-validation/repair loop, and the Scene registry rejects unknown component types.
- The desktop bridge exposes explicit methods and performs sender validation before parsing payloads.
- Hands and sessions are separated from the visible Electron browsing identity.

The implementation is a useful foundation. Passing tests confirm the covered cases; they do not establish untested integration and recovery guarantees.

**3. Product correctness issues to address first**

**A1 — Undo does not control the form used by the application. High priority; code-confirmed.**

IPC selects an action’s source with `listRepresentations(objectId).at(-1)` instead of resolving `currentVersionId`. World planning, selection lineage, cards, and the inspector likewise choose the last representation. After repository undo moves the head backward, the renderer and next transformation can still use the newest, undone output. This directly undermines the product’s central history promise. [IPC input selection](/Users/developer/development/Xeniun/apps/desktop/src/main/ipc.ts:89), [World](/Users/developer/development/Xeniun/apps/desktop/src/renderer/World.tsx:19), [UI bindings](/Users/developer/development/Xeniun/packages/ui/src/bindings.ts:41)

Fix with one canonical selected-version/form resolver used by snapshots, UI, and task input capture. Add an integration regression for undo → inspect → transform.

**A2 — Initial generation cost can disappear from a derived asset. High priority before paid use; reproduced.**

`actionsInLineage` collects action IDs from edges and adds the queried representation’s producer. A root generated without inputs has no incoming edge. When querying a descendant, the root producer is therefore omitted. In an isolated database, a $1 root generation followed by a $2 transform returned **$2 instead of $3**. The temporary database was removed after the probe. [Lineage action collection](/Users/developer/development/Xeniun/packages/graph/src/graph.ts:341)

Collect producers for every reachable representation, as well as any required edge actions, deduplicate action IDs, and test roots, diamonds, multiple roles, and shared ancestors. Keep project spend separate from per-lineage totals.

**A3 — Output persistence and version commits are separate. High priority; code-confirmed gap.**

The router inserts output representations, completes action lineage, updates model/tool fields, and commits the version in separate operations. A failure between them can leave an output without a version or a completed action without its intended head update. A later catch can mark a partly completed action failed. Version parenting is read at completion, so concurrent jobs may acquire misleading ancestry. [Router execution](/Users/developer/development/Xeniun/packages/router/src/router.ts:184), [Version commit](/Users/developer/development/Xeniun/packages/graph/src/graph.ts:402)

Stage blobs; commit graph metadata, versions, branch update, and event outbox transactionally. Capture an expected base version when scheduling work. Test failure injection and concurrent commits.

**A4 — Object metadata edits have no version snapshot. High priority for the revised product; code-confirmed.**

`object.update`/`object.move` mutate the object row and return no version. Existing versions pin one representation, not a coherent object state. `setHead` also does not check that a target version belongs to that object, and the head column has no foreign key. The graph API is append-oriented, but SQL immutability is not enforced. [Object update](/Users/developer/development/Xeniun/packages/graph/src/graph.ts:108), [Head assignment](/Users/developer/development/Xeniun/packages/graph/src/graph.ts:466), [Schema](/Users/developer/development/Xeniun/packages/graph/src/schema.ts:27)

Version object properties and representation slots. Enforce ownership/parent invariants and explicit named branches. Do not claim every MODIFY is undoable until that is true.

**A5 — New-world onboarding and capability availability are incomplete. High priority; code-confirmed.**

First-run seeds create Worlds but no objects. MockBrain’s ordinary drawing/generation paths need an existing object; the inspected bridge has no import method. The queue registers `doc.write` but no registered provider supports it. Browser tools are not registered queue handlers, and `local.playwright` appears in configuration without a corresponding provider in the registry. The desktop never constructs Hands. [First-run seeds](/Users/developer/development/Xeniun/apps/desktop/src/main/index.ts:97), [Handlers](/Users/developer/development/Xeniun/apps/desktop/src/main/services.ts:68), [Provider registry](/Users/developer/development/Xeniun/packages/providers/src/registry.ts:14), [Bridge](/Users/developer/development/Xeniun/packages/core/src/bridge.ts:62)

Make import and local object creation explicit, and give the Brain/UI an accurate executable-capability catalog. Retain interface scaffolds while showing honest unavailable explanations.

**A6 — Code preview is not fully connected to the World. Medium priority; code-confirmed.**

Preview views start at zero width/height, and although `PreviewRuntime.setBounds` exists, the code bridge/UI does not call it. World bindings do not provide `projectFiles`, and Scene planning fixes `running: false`. A generated HTML project in the graph is therefore not proof of a usable interactive preview. [Preview runtime](/Users/developer/development/Xeniun/apps/desktop/src/main/preview.ts:83), [CodePreview](/Users/developer/development/Xeniun/packages/ui/src/components/work.tsx:113), [World bindings](/Users/developer/development/Xeniun/apps/desktop/src/renderer/World.tsx:82)

Either complete the lifecycle, files, viewport bounds, and running-state bindings or keep this capability outside the first supported workflow. The current template is a basic HTML/CSS/JS scaffold, not a general React build/runtime or playable-game generator.

**4. Execution and trust gaps before remote capabilities**

**A7 — Cancellation does not stop provider execution. High priority; code-confirmed.**

The queue creates an AbortSignal, but desktop handlers do not pass it to the router and provider interfaces have no signal. Cancelling can stop queue completion reporting while the provider continues writing output. Queue `stop()` aborts and clears bookkeeping without awaiting handlers, after which services close the graph. [Queue lifecycle](/Users/developer/development/Xeniun/packages/tasks/src/queue.ts:68), [Desktop handler](/Users/developer/development/Xeniun/apps/desktop/src/main/services.ts:79), [Provider contract](/Users/developer/development/Xeniun/packages/providers/src/types.ts:55)

Propagate cancellation, await workers, prevent late commits, and distinguish requested/confirmed cancellation. Crash requeue also needs replay-safe action attempts before external effects are enabled.

**A8 — Approval is a reusable task boolean. Release blocker for consequential actions; code-confirmed.**

The queue persists `__approved: true`; the broker trusts `approved` without a plan hash, expiry, destination binding, or one-time consumption. Escalation depends partly on optional `priceUsd`/`destructive` arguments. A typed plan can still omit consequential facts. [Approval persistence](/Users/developer/development/Xeniun/packages/tasks/src/queue.ts:90), [Broker](/Users/developer/development/Xeniun/packages/permissions/src/broker.ts:51)

Use stored, plan-bound grants and adapter-derived effects. Model JSON and page labels cannot define their own authority. This is currently a latent integration risk, not evidence that a paid operation was executed in this audit.

**A9 — Hands does not enforce the boundary described in its comments. Release blocker before exposure; code-confirmed.**

An empty allowlist returns successfully, despite the comment saying it asks/denies. Initial domains are checked, but navigation redirects and later operations rely on cached domain state. `clickElement` uses MODIFY and can click arbitrary matching buttons; button clicks can submit or buy. `fillField` may reach an autosaving service. Existing same-domain drivers are reused without revalidating the grant. [Allowlist/context reuse](/Users/developer/development/Xeniun/packages/hands/src/hands.ts:156), [Click/fill](/Users/developer/development/Xeniun/packages/hands/src/hands.ts:106), [Playwright driver](/Users/developer/development/Xeniun/packages/hands/src/playwright.ts:40)

Treat effects conservatively, validate actual destinations, recheck grants, and add adversarial fixtures. Returning a receipt from Hands is not the same as durably recording the action: no integrated router/Hands path currently performs that complete sequence.

**A10 — SessionBroker accepts an unissued grant. Release blocker before identity delegation; reproduced.**

`getAutomationContext` checks caller-supplied fields and calls `isRevoked`; missing rows are treated as not revoked. A newly fabricated anonymous grant with a fresh UUID and future expiry was accepted in an isolated database. This did **not** grant authenticated cookies: M1 returns anonymous contexts. It does show that issuance is not enforced. [Grant verification](/Users/developer/development/Xeniun/packages/sessions/src/broker.ts:72), [Revocation check](/Users/developer/development/Xeniun/packages/sessions/src/broker.ts:99)

Load the canonical row and validate task/domain/scope/expiry on every use. The queue currently handles `ApprovalRequired`, but not `IdentityRequiredError` as a resumable identity state. The default identity probe returns nothing, and the displayed sign-in/delegation instruction cannot complete an M1 flow. Make that limitation explicit.

**A11 — Electron isolation is partially implemented, not fully established. High priority before broad browsing; code-confirmed gaps, not exploit-tested.**

Development renderer trust uses `startsWith(DEV_URL)`; session trust checks storage-path strings rather than equality with a registered privileged Session. Production navigation permits any `file://` navigation even though IPC matching is narrower. Remote popup handling calls `shell.openExternal` before denying the Electron window, so “window.open is blocked” does not mean “nothing opens.” Preview navigation also uses a prefix test and shares one persistent preview partition. [App trust/navigation](/Users/developer/development/Xeniun/apps/desktop/src/main/index.ts:48), [Session check](/Users/developer/development/Xeniun/apps/desktop/src/main/security.ts:65), [Popup handler](/Users/developer/development/Xeniun/apps/desktop/src/main/browser.ts:42), [Preview](/Users/developer/development/Xeniun/apps/desktop/src/main/preview.ts:78)

Use exact URL/origin/session comparisons, a dedicated app protocol, explicit external-link actions, and per-object/run preview isolation. The preview CSP alone does not prove the comment’s “no network” guarantee across navigation, forms, workers, and redirects; verify those channels in Electron. IPC also rethrows ordinary handler errors, so it does not consistently return the typed error envelope described in the plan. Follow current Electron guidance and add runtime smoke tests. [Electron security guidance](https://www.electronjs.org/docs/latest/tutorial/security)

**A12 — Paid execution is not yet budget-safe. Release blocker before enabling providers; code-confirmed.**

The router compares estimates to settled action costs without reserving concurrent spend; unknown prices return zero. Failure handling defaults cost to zero, and Brain token accounting is not recorded in the router ledger. Cloud image/Meshy/Runway implementations are stubs whose availability always ends in “not implemented,” even when enabled and keyed. [Budget checks](/Users/developer/development/Xeniun/packages/router/src/router.ts:128), [Estimate fallback](/Users/developer/development/Xeniun/packages/router/src/router.ts:285), [Cloud stubs](/Users/developer/development/Xeniun/packages/providers/src/cloud/stubs.ts:14)

Keep them disabled until real adapters, verified quotes, reservations, settlement, retry accounting, and disclosure policy exist. Provider swapping is a useful boundary, but the existing interfaces will need cancellation, async jobs, and richer validation; it is not solely a configuration change.

**A13 — Type names overstate some runtime guarantees. Medium/high priority; code-confirmed.**

The outer ActionPlan is strict, but `args` is `z.record(z.unknown())`; provider results are TypeScript interfaces without runtime output parsing. Many local inputs are coerced or inspected ad hoc. `parseProject` trusts a JSON cast. The renderer-boundary checks do not establish modality compatibility, safe paths, bounded resources, or valid generated content. [ActionPlan](/Users/developer/development/Xeniun/packages/core/src/action.ts:37), [Provider contracts](/Users/developer/development/Xeniun/packages/providers/src/types.ts:17), [Virtual project parser](/Users/developer/development/Xeniun/packages/providers/src/local/template.ts:14)

Add strict schemas and semantic validation per capability, verify output formats, and check object/world ownership. Validation of “a string exists” is different from validation that a job is executable and authorized.

**5. Important limits of the current demonstration**

- The loop contains **five versions and four transformation transitions**, not five transformation edges.
- A recorded input edge establishes recorded attribution. The procedural mock mesh does not prove semantic image-to-3D fidelity.
- The loop’s STL check covers binary structure/length and triangle data, not manifoldness, print settings, or an actual slicer/print.
- The “game-ready” step scales/smooths a mesh; it does not test a game-engine import, materials, triangle budget, collisions, or gameplay.
- A deterministic operation after a mock input has deterministic direct provenance and mock ancestry. The current badge shows the direct field, so exported descendants need explicit inherited-origin reporting.
- The graph demo’s success cannot establish desktop undo behavior, because its checks call the repository API directly.
- Numbered migration strings are embedded in TypeScript and applied transaction-by-transaction; the implementation differs from the supplied description of external SQL files. That packaging choice is reasonable and does not require a rewrite.
- The existing Node/Electron ABI marker records only the target family. Runtime version/architecture changes and failed rebuilds need a more robust artifact check. The build still needs clean-machine packaging, bundled-resource checks, and supported-runtime maintenance.
- No README, license, contribution/security documentation, or CI configuration was found in the inspected project. Public open-source release needs those even if the original internal scaffold deferred them.

**6. Priority for the next implementation pass**

First repair current-head use, root-generation cost, grant issuance validation, and truthful capability availability. Then add real import, coherent version snapshots, transaction-safe commits, and cancellation. Build the revision/delivery workflow on that base. Keep remote/browser features gated until their action, policy, identity, and receipt paths are complete.

The revised plan turns these observations into release gates. The aim is to preserve the prototype’s useful foundations while making its central promises observable in real user work.
